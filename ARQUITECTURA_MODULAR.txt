=====================================================================
ARQUITECTURA MODULAR DE CONTROLADORES
Guía de Refactorización para Reducir Código Repetitivo
=====================================================================

PROBLEMA IDENTIFICADO:
---------------------
Los controladores actuales (JugadorControlador, PartidoControlador, 
EventoJugadorControlador) tienen mucho código duplicado:

- Mismo patrón CRUD: GET /{id}, POST /, PUT /{id}, DELETE /{id}
- Misma lógica de conversión DTO ↔ Entity usando mappers
- Misma estructura de ResponseEntity
- Misma gestión de excepciones

Esto genera:
❌ Código repetitivo difícil de mantener
❌ Mayor probabilidad de bugs al copiar/pegar
❌ Dificultad para aplicar cambios globales
❌ Violación del principio DRY (Don't Repeat Yourself)


SOLUCIÓN: CONTROLADOR BASE GENÉRICO
-----------------------------------

Hemos creado una arquitectura modular usando:

1. **BaseController<E, D, ID>** - Controlador abstracto genérico
   - Implementa operaciones CRUD comunes
   - Usa genéricos para adaptarse a cualquier entidad
   - E = Entidad (Jugador, Partido, Equipo, etc.)
   - D = DTO correspondiente
   - ID = Tipo del identificador (Long, String, etc.)

2. **BaseService<E, ID>** - Interfaz de servicio genérico
   - Define contrato común para todos los servicios
   - findById, findAll, save, update, delete


VENTAJAS DE LA NUEVA ARQUITECTURA:
----------------------------------

✅ **Reducción de código**: 70-80% menos líneas en controladores
✅ **Consistencia**: Todos los endpoints CRUD se comportan igual
✅ **Mantenibilidad**: Cambios en BaseController afectan a todos
✅ **Testabilidad**: Fácil de probar con clases base
✅ **Extensibilidad**: Solo añades endpoints específicos del recurso
✅ **Documentación clara**: Swagger documenta métodos heredados
✅ **Menos bugs**: Código probado compartido entre controladores

CÓMO MIGRAR CONTROLADORES EXISTENTES
=====================================================================

PASO 1: IDENTIFICAR ENDPOINTS COMUNES
--------------------------------------
En cada controlador, marca los endpoints que son genéricos:

✓ GET /{id}           → Heredar de BaseController
✓ GET /               → Heredar de BaseController
✓ POST /              → Heredar de BaseController
✓ PUT /{id}           → Heredar de BaseController
✓ DELETE /{id}        → Heredar de BaseController

✗ GET /equipo/{id}    → Mantener (específico)
✗ PUT /{id}/activar   → Mantener (específico)


PASO 2: CREAR NUEVO CONTROLADOR
--------------------------------
1. Crear nueva clase que extienda BaseController
2. Especificar tipos genéricos: <Entidad, DTO, ID>
3. Implementar métodos abstractos: getService(), toDto(), toEntity()

@RestController
@RequestMapping("/api/v1/jugadores")
@CrossOrigin(origins = "http://localhost:4200")
public class JugadorControladorV2 extends BaseController<Jugador, JugadorDTO, Long> {

    @Autowired
    private JugadorService jugadorService;

    @Autowired
    private JugadorMapper jugadorMapper;

    @Autowired
    private EquipoService equipoService;

    // Implementar BaseService adapter
    @Override
    protected BaseService<Jugador, Long> getService() {
        return new BaseService<Jugador, Long>() {
            @Override
            public Jugador findById(Long id) {
                return jugadorService.obtenerJugadorPorId(id);
            }

            @Override
            public List<Jugador> findAll() {
                // Podrías necesitar contexto de autenticación aquí
                return jugadorService.obtenerTodos();
            }

            @Override
            public Jugador save(Jugador entity) {
                return jugadorService.guardar(entity);
            }

            @Override
            public Jugador update(Long id, Jugador entity) {
                return jugadorService.actualizar(id, entity);
            }

            @Override
            public void delete(Long id) {
                jugadorService.eliminar(id);
            }
        };
    }

    @Override
    protected JugadorDTO toDto(Jugador entity) {
        return jugadorMapper.toDto(entity);
    }

    @Override
    protected Jugador toEntity(JugadorDTO dto) {
        return jugadorMapper.toEntity(dto);
    }

    // ========== ENDPOINTS ESPECÍFICOS ==========

    /**
     * GET /api/v1/jugadores?equipoId=X
     * Listar jugadores con filtro opcional por equipo
     */
    @GetMapping
    @Override
    public ResponseEntity<List<JugadorDTO>> getAll(
            @RequestParam(required = false) Long equipoId,
            Authentication authentication) {
        
        if (equipoId != null) {
            List<Jugador> jugadores = jugadorService.obtenerPorEquipo(equipoId);
            return ResponseEntity.ok(jugadores.stream()
                    .map(jugadorMapper::toDto)
                    .collect(Collectors.toList()));
        }

        if (authentication == null) {
            return ResponseEntity.status(401).build();
        }

        String username = authentication.getName();
        Usuario usuario = usuarioRepository.findByUsername(username);
        if (usuario == null) {
            return ResponseEntity.status(404).build();
        }

        List<Jugador> jugadores = jugadorService.obtenerPorUsuario(usuario.getId());
        return ResponseEntity.ok(jugadores.stream()
                .map(jugadorMapper::toDto)
                .collect(Collectors.toList()));
    }

    /**
     * GET /api/v1/jugadores/equipo/{equipoId}
     * Obtener jugadores de un equipo específico
     */
    @GetMapping("/equipo/{equipoId}")
    public ResponseEntity<List<JugadorDTO>> getByEquipo(@PathVariable Long equipoId) {
        List<Jugador> jugadores = jugadorService.obtenerPorEquipo(equipoId);
        return ResponseEntity.ok(jugadores.stream()
                .map(jugadorMapper::toDto)
                .collect(Collectors.toList()));
    }

    /**
     * POST / - Override para añadir validación de equipo
     */
    @PostMapping
    @Override
    public ResponseEntity<JugadorDTO> create(@RequestBody JugadorDTO dto) {
        if (dto.getEquipoId() == null) {
            throw new RuntimeException("Debe proporcionar un equipoId válido");
        }

        Equipo equipo = equipoService.obtenerEquipoPorId(dto.getEquipoId());
        if (equipo == null) {
            throw new ResourceNotFoundException("No existe el equipo con ID: " + dto.getEquipoId());
        }

        Jugador jugador = jugadorMapper.toEntity(dto);
        jugador.setEquipo(equipo);

        Jugador guardado = jugadorService.guardar(jugador);
        return ResponseEntity.status(HttpStatus.CREATED).body(jugadorMapper.toDto(guardado));
    }
}

CONSIDERACIONES ESPECIALES
=====================================================================

1. AUTENTICACIÓN:
   Si algunos endpoints requieren autenticación, puedes:
   - Usar @PreAuthorize en BaseController
   - Override endpoints específicos con lógica de auth
   - Usar SecurityContext en getService()

2. VALIDACIONES COMPLEJAS:
   Para validaciones específicas:
   - Override el método base (ej: create, update)
   - Añade validación antes de llamar a super.create()
   - O maneja en el servicio

3. RESPUESTAS PERSONALIZADAS:
   Si necesitas formato diferente de respuesta:
   - Override el método completo
   - O crea endpoint adicional con otro path

4. PAGINACIÓN:
   Para añadir paginación:
   - Añade método adicional: GET /?page=X&size=Y
   - O modifica getAll() para soportar Pageable

DECISIÓN: ¿MIGRAR O NO?
=====================================================================

MIGRAR SI:
✅ Tienes 3+ controladores con patrón similar
✅ Planeas añadir más recursos/entidades
✅ Quieres mejorar mantenibilidad
✅ Necesitas consistencia en la API
✅ Valoras código limpio y DRY

NO MIGRAR SI:
❌ Proyecto pequeño (1-2 controladores)
❌ Cada controlador es muy diferente
❌ No habrá mantenimiento futuro
❌ Equipo no familiarizado con genéricos
